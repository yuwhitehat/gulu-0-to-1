| **BC-004** | 2026-10-15 | **定时任务仍建不出来**（引导结束创建任务失败/不生效） | `AGENTS.md` 已写"不直连 / 不出现端点"，但 **`proactive-message/SKILL.md` 等 skill 正文仍描述旧的命令行式创建方法**，AI 跟着 skill 走 | 创建方式统一为**动态工具**：`schedule.create`（`kind=prompt`）/ `schedule.list_own` / `schedule.update`；清理 skill 正文旧表述 | ✅ 已修 v0.34 |

| **BC-005** | 2026-10-15 | **应用侧自查仍有命中**（外部地址 / 端口 / 命令行请求字样） | 命中的都是**禁令本身引用了那些字样**（无实际调用），但按验收口径要求 0 命中 | 改成正向规则（"只用动态工具，不得采用其它任何方式"）；新增"验收口径"行 | ✅ 已修 v0.36 |

| **BC-006** | 2026-10-15 | **定时任务触发后群里出现两条一模一样的消息** | Bot 的 **ResultDelivery** 会自动投递 Agent 的最终回复；而 v0.35/v0.36 的文档让 Agent **又显式调了一次发消息工具** → 投递两次 | `AGENTS.md` 新增「定时任务触发后的消息发送（重要）」：**只输出最终回复，不要调用 `feishu.message_send_current_channel`**；`delivery_mode` 明确为投递开关；删除 `record_send` | ✅ 已修 v0.37 |
